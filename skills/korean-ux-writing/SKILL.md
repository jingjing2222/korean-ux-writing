# Korean UX Writing

사용자가 자신의 목적과 지금까지 받은 안내만으로 행동과 결과를 이해할 수 있는지 먼저 확인한다. **맥락을 기록하기 전에 문구를 진단하거나 고치지 않는다.**

## 공통 경계

- 영어 원문이 없는 한국어 제품을 기본으로 본다. 가상의 영문을 복원하거나 번역 기원을 단정하지 않는다.
- 기존 한국어만 다듬는다. 다른 언어는 맥락으로 읽되 그대로 두고, 혼합 문장의 영문·제품명·명령어·식별자도 보존한다. 별도 언어 작업은 사용자가 요청한 범위에서만 한다. 한국어가 없으면 그 사실을 알린다.
- 제품 코드·사양은 동작의 근거다. UX 자료는 무엇을 언제 안내할지, 한국어 자료는 어떻게 표현할지 판단하는 근거다.
- 검토자의 내부 지식과 사용자에게 제공된 정보를 구분한다. 에이전트 점검을 실제 참여자 관찰로 보고하지 않는다.

## 현재 단계의 지침만 읽는다

**처음에는 [1. 맥락 파악](references/context.md)만 읽고 실행한다.** 아래 표는 진행 순서이며 전체 문서를 미리 읽으라는 목록이 아니다. 규칙·진단 기준·감사 형식도 해당 단계에서 필요해질 때 읽는다. 모든 참고 파일을 한꺼번에 열거나, 아직 없는 맥락을 규칙으로 추측하지 않는다.

| 단계 | 이 단계에서 답할 질문 | 다음 단계에 넘길 결과 |
|---|---|---|
| [1. 맥락 파악](references/context.md) | 누가 무엇을 하려 하며, 각 경로에서 무엇을 알고 어떤 결과를 얻는가? | 원문·사용처, 사용자에게 보인 정보와 예상, 확인한 동작·조건, 남은 질문을 담은 맥락 기록 |
| [2. 의미 진단](references/diagnosis.md) | 이 맥락에서 필요한 안내와 현재 한국어의 뜻이 맞는가? | 사용처별 진단·흐름 문제와 `kuw prepare`로 검사·보관한 진단, 수정용 보고서 |
| [3. 윤문](references/revision.md) | 확인한 의미 차이를 어떤 한국어로 해결할 것인가? | 수정·유지·보류 결정과 실제 diff |
| [4. 재검증](references/verification.md) | 같은 경로를 다시 따라가도 문제가 해결됐는가? | `kuw audit --require-checkpoint`로 검사한 감사와 미해결 사항, 확인한 범위의 결과 보고 |

각 단계의 결과를 저장한 뒤 다음 문서를 읽는다. 단계 전환은 사용자 승인 절차가 아니며, 이미 허용된 작업은 계속한다. 근거가 부족하면 답할 질문을 좁혀 앞 단계로 돌아간다. 관련 없는 경로까지 멈추거나 같은 자료를 이유 없이 다시 읽지 않는다.

재개할 때는 기존 기록과 현재 제품이 같은 버전·범위인지 확인한다. 유효한 결과를 재사용하고, 바뀐 경로는 맥락부터 다시 확인한다. 이후 알게 된 사실로 이전의 예상 기록을 고치지 않는다. 필요한 자료가 없는 문구는 보류하되 확인 가능한 경로는 계속한다.

각 단계에서 무엇을 확인했고 무엇이 남았는지 짧게 알린다. 기록 형식 검사가 통과해도 실제 맥락·판단·작업 순서가 검증된 것은 아니다. 확인하지 못한 경로와 해결하지 못한 흐름 문제는 최종 결과에 남긴다.
