# Korean UX Writing

퍼널 전체를 이해한 뒤 한국어 UI 문구를 다듬는다. 코드는 실제 동작을 확인하는 자료다. UX 근거는 필요한 안내를 결정하고, 한국어 근거는 그 뜻을 어떻게 표현할지 결정한다.

프로젝트 읽기 권한과 Python 3.10 이상이 필요하다. 실제 화면은 호스트 에이전트에서 사용할 수 있는 도구로 확인한다.

## 시작할 때

1. [워크플로](references/workflow.md)를 읽는다. 파일 하나를 요청받아도 그 파일이 속한 퍼널의 앞뒤 맥락과 모든 관련 분기를 먼저 읽는다.
2. [규칙](references/rules.json), [번역투 진단 기준](references/translationese.json), [출처 잠금 정보](sources.lock.json)를 읽는다. 아래 도구로 고정된 증적을 가져온 뒤 적용할 규칙의 출처·해당 절·조건·예외를 확인한다.
3. [감사 기록 형식](references/audit-format.md)에 따라 작업 기록을 만든다. 대장을 작성하기 전에 발견한 문구부터 수정하지 않는다.

```sh
python3 <skill-directory>/scripts/evidence.py --out .reports/korean-ux-writing/sources.json
```

`<skill-directory>`는 설치된 이 `SKILL.md`가 있는 디렉터리다. 프로젝트 루트에 스킬 원본 레포의 `docs/`가 있다고 가정하지 않는다. 원본 체크아웃에서는 `--source docs/evidence/sources.json`을 추가해 같은 해시의 로컬 증적을 사용할 수 있다.

## 1. 영향을 받는 퍼널 전체를 읽는다

범위가 지정되지 않았다면 프론트엔드 전체를 조사한다. 라우트·화면·상태·권한·기능 플래그와 공용 컴포넌트의 모든 사용처를 확인한다. 한국어 검색 결과만으로 범위를 확정하지 않는다.

각 퍼널의 진입점, 앞 단계의 약속과 입력, 현재 선택, 조건별 전이, 뒤 단계의 결과, 완료·실패·취소·뒤로 가기·재시도 경로를 연결한다. 라우터, 호출부, 상태 관리, 검증 코드, 요청·응답 처리, 번역 리소스를 따라 읽는다. 서로 다른 퍼널에서 공유하는 문구는 모든 사용처의 맥락을 읽는다.

앞 단계에서 정한 대상·금액·기간·약속과 뒤 단계에서 실제로 일어나는 일을 확인하기 전에는 해당 문구를 고치지 않는다. 성공 응답, 접수, 처리 중, 실제 완료를 구분한다. 연결된 코드나 동작을 확인할 수 없으면 추측하지 말고 해당 항목과 퍼널을 `blocked`로 기록한다. 확인 가능한 다른 퍼널은 계속 진행한다.

## 2. 모든 문구를 맥락별로 대장에 기록한다

버튼·제목·본문·입력 안내·오류·로딩·빈 화면·토스트·모달·링크·접근성 이름·대체 텍스트·페이지 제목을 포함한다. 번역 키, 문자열 결합, 조건 분기, 서버/CMS 문구, 이미지 속 문구도 조사한다. 사용자 작성 콘텐츠는 제품 문구와 구분해 범위를 설명한다.

동일한 글자라도 역할이 다르면 별도 항목이다. 실제로 공유되는 키는 모든 사용처를 연결하고 함께 검토한다. 조각난 JSX 문장은 하나의 논리 문구로 읽되 원본 위치를 모두 남긴다. 동적 문구는 템플릿과 각 분기, 대표 값으로 조사·어미가 맞는지도 확인한다.

원문과 ID를 먼저 고정한다. 모든 항목은 수정 후 문구 하나 또는 명시적인 유지·보류 판정과 대응해야 한다.

## 3. 윤문 전에 직역체·번역투를 진단한다

원문을 고정한 대장의 모든 문구에서 `LT-05`를 먼저 검토한다. **문법이 맞아도 영어 표현의 틀을 따라 한국어 UI에서는 어색한 어휘·결합이 될 수 있다.** 실제 안내 의도와 행동을 `intent`에, 현재 표현이 그 역할의 한국어로 적절한지 구체적 이유를 `korean_fit`에 적는다. 단순히 다음 행동이 정확한지만 보지 말고, 그 행동과 대상을 한국어에서 어떻게 부르는지도 확인한다.

외국어 원문이 있으면 단어별 대응과 전달 의도를 구분해 대조한다. 없으면 번역이나 AI 생성에서 비롯됐다고 추정하지 않는다. 이어 `LT-01~04`로 구문·복수 표현·전치사구·일한 표현 간섭을 보조 점검한다. 형태상 특징이 없다는 이유로 진단을 끝내지 않는다.

각 문구를 `candidate`(표현 재검토 후보), `clear`(이 기준에서 후보 없음), `uncertain`(판단 보류)로 기록한다. 후보 구절, 적용 기준, 문맥 근거, 정상 용례·예외 검토를 남긴다. 피동형이나 특정 단어가 있다는 이유만으로 후보로 확정하지 않는다. 과장·군더더기·맞춤법 오류는 별도로 판단한다.

첫 수정 전에 진단 기록을 저장하고 검사한다.

```sh
python3 <skill-directory>/scripts/audit.py .reports/korean-ux-writing/diagnosis.json --diagnosis-only
```

이 검사는 진단 누락과 기록 형식을 확인한다. 실제 문장 진단은 에이전트가 근거와 맥락을 읽고 수행한다. 후보 판정만으로 교정하지 않으며, 표현을 바꿀 필요와 의미 보존 가능성을 다음 두 단계에서 판단한다. 최종 대장에도 같은 원문과 진단을 남긴다.

## 4. UX가 요구하는 안내를 먼저 확정한다

해당 시점에 사용자가 아는 것, 결정해야 하는 것, 꼭 알아야 할 조건, 다음 행동과 결과를 적는다. `UX-*` 규칙과 외부 증적을 연결한다. 기능·오류 원인·복구 방법의 사실 근거는 코드나 실제 UI에서 별도로 남긴다.

필요한 안내가 빠졌다면 확인된 사실만 보충한다. 기존 안내가 실제 동작과 다르면 이 단계에서 사실에 맞게 바로잡고, 원래 주장·확인한 사실·확인 위치를 별도로 기록한다. 사실을 확인하지 못했다면 보류한다. 복구 버튼이나 다음 단계가 없다면 문구로 존재하는 척하지 않는다. 동작·구조 변경이 필요한 문제는 별도로 보고하고, 윤문 작업에서 결제·동의·권한·탐색 동작을 바꾸지 않는다.

## 5. 의미를 보존하며 한국어를 다듬는다

확정한 UX 요구사항을 기준으로 `KO-*` 규칙을 적용한다. 어휘·어순·문장 길이·높임·조사·띄어쓰기·문장부호를 검토한다. 적용한 규칙마다 왜 이 맥락에 맞는지 설명한다.

해요체, 긍정형, 능동형, `-하기`, 외래어 제거를 일괄 강제하지 않는다. 제품의 문서화된 말투와 용어는 제약으로 확인하되 기존 문구 자체를 좋은 한국어의 증거로 삼지 않는다. 문체가 정해지지 않았으면 새 브랜드 말투를 발명하지 않는다.

윤문 단계에서는 앞서 사실로 확정한 조건·예외·부정·확정성·책임 주체·금액·기간·단위를 바꾸지 않는다. 보존 대상은 확인한 제품의 의미이며, 잘못된 기존 안내까지 그대로 유지하라는 뜻이 아니다. 변수, ICU 분기, 태그, 번역 키, 접근성 이름의 관계도 보존한다. ‘더 자연스럽다’는 취향이나 AI 문체 탐지 점수만으로 수정하지 않는다.

좋은 문구는 `keep`으로 남긴다. 근거가 충돌하거나 정보가 부족하면 `blocked`로 남긴다. 출처 없는 새 표현 규칙을 만들어 빈틈을 메우지 않는다. 새 기준은 원문 검토와 레포의 증적 변경을 거친 별도 버전에서 다룬다.

## 6. 퍼널을 다시 따라가며 검증한다

진입부터 끝까지 변경 문구를 이어 읽고 모든 관련 분기를 재검토한다. 앞 단계와 약속이 맞는지, 다른 상태의 문구와 모순되지 않는지, 다음 행동을 실제로 할 수 있는지 확인한다. 가능한 환경에서는 렌더링·접근성·줄바꿈과 잘림도 확인한다. 실행하지 못한 검증은 성공으로 기록하지 않는다.

```sh
python3 <skill-directory>/scripts/audit.py .reports/korean-ux-writing/audit.json --require-complete
```

도구는 기록의 대응과 구조·토큰 보존을 검사한다. 문구 발견의 완전성, 의미의 정확성, 자연스러움을 증명하지 않는다. 코드·퍼널·화면을 읽은 검토가 반드시 필요하다.

## 결과 보고

검토한 범위, 수정·유지·보류 수, 주요 개선과 검증 결과를 짧게 알린다. 상세 대장에는 각 항목의 원문·수정문·퍼널 맥락·UX 근거·한국어 근거·사실 확인 위치를 남긴다.

미확인 경로, 사용처, 문구, 상태 또는 화면 검증이 남으면 전체 완료로 보고하지 않는다. 알려진 문제를 검토 범위에서 빼서 완료율을 높이지 않는다. ‘AI slop이 절대 없다’는 보장 대신 적용한 기준과 남은 한계를 보고한다.
