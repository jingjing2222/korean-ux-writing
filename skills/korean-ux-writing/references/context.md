# 1. 맥락 파악

지금은 독자·과업·경로와 사실을 확인한다. 문구의 좋고 나쁨, 번역투 여부, 개선 문장은 아직 정하지 않는다. 규칙 카탈로그·진단 기준·감사 형식은 다음 단계에서 읽는다.

## 질문부터 좁힌다

사용자가 정한 범위와 현재 자료를 확인한다. 범위가 없는 프론트엔드 검토는 전체를 조사하되 작은 개요부터 경로를 찾아 확장한다. 문구 검색 결과를 전체 범위로 대신하지 않는다. 이미 있는 기록은 대상 버전과 범위가 일치하는지 확인해 재사용한다.

먼저 누가 무엇을 이루려는지, 어디로 들어오는지, 지금 어떤 선택을 해야 하는지를 적는다. 실제 조사 자료가 없다면 과업·독자에 관한 가설임을 밝힌다. 전문 독자에게 익숙한 지식까지 없다고 가정하지 않는다. UI의 최종 사용자와 README를 읽는 개발자, 내부 검토자를 구분한다.

## 사용자에게 보이는 정보부터 따라간다

가능하면 구현을 읽기 전에 해당 경로의 안내를 순서대로 확인한다. 매 단계에서 이미 받은 정보, 현재 선택과 예상 결과, 알 수 없는 것을 먼저 남긴다. 이후 화면·결과나 코드에서 확인한 실제 동작은 별도로 기록한다. 내부 내용을 이미 알고 있다면 그 사실을 밝히며 모르는 척한 최초 반응을 만들지 않는다.

다른 분기·나중 화면·세션 설명을 현재 사용자가 아는 정보로 넣지 않는다. 화면에 있음을 읽고 이해했다는 증거로 삼지 않는다. 정적 자료만 읽었다면 렌더링·발견 가능성·실제 참여자 반응을 관찰했다고 하지 않는다.

한 번에 모든 구현을 펼치기보다 남은 질문에 필요한 호출부·조건·결과를 좁혀 읽는다. 파일명·키·핸들러 이름만으로 동작을 확정하지 않는다. 확인한 사실, 해석, 미확인 사항과 위치를 구분한다. 결과가 없으면 이를 메울 문구를 만들지 않는다.

## 읽는 범위와 수정하는 범위

한국어 윤문 요청은 기존 한국어를 고칠 권한이다. 영어·다른 언어의 화면과 자료도 퍼널 맥락으로 읽지만, 이를 한국어로 번역하거나 다른 언어의 문장을 교정하지 않는다. 쉬운 표현, 용어 통일, 사용자 이해를 이유로 이 경계를 넓히지 않는다. 다른 언어의 작성·번역·교정은 별도로 요청된 경우에만 그 범위에서 수행한다.

- **기존 한국어:** 원문과 모든 사용처를 모은다. 한글로 쓰인 외래어도 포함한다.
- **한국어와 다른 언어가 섞인 문구:** 문장 전체와 위치를 남기고, 보존할 외국어 구절·제품명·약어·명령어·식별자를 원래 표기대로 기록한다.
- **다른 언어로만 된 문구:** 원문과 위치를 맥락 자료로 기록하되 한국어 수정 대상에 넣지 않는다. 읽었다는 사실만으로 번역·교정 권한이 생기지 않는다.

맥락 기록에 수정 대상과 맥락으로만 읽는 대상을 구분한다. 파일 경로나 한글 포함 여부만으로 권한을 정하지 말고 실제 문구와 로케일을 확인한다. 다른 언어의 화면에서 이해하지 못한 점도 원문과 함께 남긴다. 한국어 표현이 전혀 없다면 수정할 한국어가 없다고 보고하고, 대장을 채우려고 번역하지 않는다.

## 범위와 퍼널

먼저 사용자가 지정한 앱·문서의 진입점과 개요를 확인한다. UI라면 라우트 설정, 화면 목록, 번역 리소스와 공유 UI를 찾는다. 기존 테스트·스토리·제품 사양은 누락된 상태를 찾는 보조 자료다. 변경된 파일만 읽는 것으로 퍼널을 파악했다고 판단하지 않는다.

퍼널은 사용자의 목적에 따라 정한다. 예를 들어 구독 변경에는 요금제 선택뿐 아니라 현재 이용 조건, 변경 확인, 결제 요청, 접수·완료, 실패·취소, 변경 후 안내가 포함될 수 있다. 실제 코드에 없는 단계를 이 예시에서 복제하지 않는다.

README·설치 안내·도움말의 퍼널은 문단 목록으로 대신하지 않는다. 문서가 안내한 선택·명령 실행·생성물 수정·이후 작업과 관련 도움말·오류를 연결한다. 문단을 읽은 위치와 실제로 선택·실행하는 시점을 따로 기록한다.

퍼널마다 다음 사실을 기록한다.

| 확인할 맥락 | 읽을 자료와 질문 |
|---|---|
| 진입 | 어디에서 들어오는가? 딥링크나 재방문으로 중간 진입이 가능한가? |
| 앞 단계 | 이 진입 경로에서 실제로 제공한 약속·가격·조건·입력은 무엇인가? 필요한 순간에 다시 찾을 수 있는가? 노출 사실을 이해·기억의 증거로 삼지 않았는가? |
| 현재 단계 | 무엇을 결정하고 어떤 데이터를 다루는가? 버튼은 무엇을 실제로 실행하는가? |
| 분기 | 로그인·권한·검증·기능 플래그·응답 값에 따라 무엇이 달라지는가? |
| 뒤 단계 | 버튼 직후와 최종 결과는 각각 무엇인가? 추가 확인이나 처리가 남아 있는가? |
| 복구와 종료 | 뒤로 가기·취소·재시도 시 입력과 상태는 어떻게 되는가? 되돌릴 수 있는가? |
| 공유 사용처 | 같은 컴포넌트·번역 키가 다른 퍼널에서도 같은 의미로 쓰이는가? |

UI 코드에서 핸들러와 상태 업데이트, 호출하는 서비스·API 처리까지 따라간다. 서버의 실제 결과를 알 수 없으면 프론트엔드가 보장하는 범위를 넘어서 말하지 않는다. 라우트 한 페이지가 상태 여러 개를 담을 수 있고, 한 퍼널이 여러 파일·페이지를 가로지를 수 있다.

파일을 읽었다는 기록에는 경로만 적지 않는다. 확인한 분기·행동·조건과 코드 위치를 적는다. 전체 퍼널의 경계를 코드로 설명할 수 있을 때까지 관련 호출부를 조사한다. 조사하지 못한 경로는 남은 질문으로 기록해 다음 단계와 최종 감사에 넘긴다.

상태는 문구의 의미·노출·행동·결과가 달라지는 지점에서 나눈다. 같은 DOM 위치라도 저장 전과 저장 후에 안내의 의미가 달라지면 각각 연결한다. 의미와 동작이 같은 값의 조합은 함께 검토할 수 있지만, 묶은 조건과 같다고 판단한 근거를 남긴다. 모든 변수 조합을 기계적으로 늘리거나, 실제 차이를 합쳐 누락하지 않는다.

## 수집

제목·본문·버튼·링크·입력 안내·오류·로딩·빈 화면·알림·모달·접근성 이름·대체 텍스트·문서 제목을 포함한다. 동적 문장과 분기, 서버/CMS, 이미지 속 문구도 조사하고 사용자 콘텐츠는 구분한다.

코드의 문자열 리터럴만 수집하지 않는다. 렌더링되는 사용자 문구를 아래 경로에서 대조한다.

- 화면·공용 컴포넌트의 텍스트 노드와 props, 명령형 토스트·대화창 호출.
- 번역 리소스와 번역 함수 호출부, 기본값·대체 언어·키 누락 처리.
- 검증 라이브러리의 메시지, 에러 코드 매핑, 서버에서 그대로 전달되는 문구.
- 접근성 이름·설명·대체 텍스트·상태 안내, 문서 제목.
- 문자열 보간·복수형·ICU select/plural·값에 따라 달라지는 조사.
- 권한·기능 플래그·인증·네트워크·빈 데이터 등 조건별 화면.
- 이미지·SVG·캔버스에 들어간 제품 문구. 읽기나 수정이 불가능하면 그 한계를 기록한다.

정적 검색, 구문·호출부 확인, 라우트·상태 목록, 실행 화면을 서로 대조한다. 한 방법의 결과 수를 전체 문구의 분모로 선언하지 않는다. 지원하지 않는 파일 형식, 접근 불가능한 CMS·서버 리소스, 실행하지 못한 상태를 명시한다.

## 다음 단계로 넘길 기록

작업용 보고서 폴더에 `context.json`을 저장한다. 이 파일은 맥락을 넘기는 작업 기록이며 네이티브 감사 스키마가 아니다. 기존 형식의 동등한 기록이 있다면 중복 작성하지 않고 위치를 연결한다.

- 독자·과업·범위·버전과 그 근거 또는 가설, 시작할 때 알고 있던 내부 정보.
- 질문별 확인 자료와 결과. 각 경로의 제공 정보·행동 전 예상·실제 결과를 구분한 순서 기록.
- 기존 한국어 원문과 모든 사용처, 다른 언어의 맥락 자료, 보존할 식별자·변수·조건.
- 확인한 분기·조건·예외·결과와 위치, 확인하지 못한 경로·남은 질문.

원문을 고치거나 `candidate`·`clear` 판정으로 빈 맥락을 채우지 않는다. 같은 키가 다른 과업에 쓰이면 그 차이를 남긴다. 다음 단계에서 의미별 ID를 확정한다.

확인 가능한 각 경로에서 누가 무엇을 알고 선택하며 어떤 결과를 얻는지 설명할 수 있고, 미확인 부분이 구분됐으면 [2. 의미 진단](diagnosis.md)을 읽는다. 특정 경로가 미확인이라는 이유로 독립적으로 확인한 경로까지 막지는 않는다.
