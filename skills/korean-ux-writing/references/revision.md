# 3. 윤문

`kuw prepare`가 만든 폴더의 `audit.json`과 `user-perspective.json`에서 작업한다. 원문·사용처 ID를 다시 옮겨 적지 않는다. 도구가 만든 결정 항목에 판정·개선문·이유·사용처별 근거를 채운다. `checkpoint.json`과 보고서의 `checkpoint_ref`·`checkpoint_sha256`은 그대로 둔다. 진단을 바꿔야 하면 2단계에서 새 기록을 준비한다.

이 단계부터 [규칙](rules.json)의 필요한 `KO-*`와 그 출처를 읽고 대안을 만든다.

## 뜻의 문제를 해결한 다음 표현을 다듬는다

`candidate`의 수정·유지 이유를 `diagnosis_resolution`에 연결한다. 어떤 뜻의 차이를 해소했는지, 어떤 예외·제약 때문에 그대로 두는지 설명한다. 어미만 바꿔 확인한 의미 문제를 해결했다고 하지 않는다. `uncertain`은 새 근거로 진단을 갱신하기 전까지 `blocked` 또는 `excluded`로 보존한다.

선행 맥락 누락 여부를 먼저 판단한다. 필요한 안내가 이전 경로에 없었다면 `ux_findings`에 흐름 문제와 적절한 제공 시점을 기록한다. 그 문제를 현재 문구의 설명 추가로 대신하지 않는다. 표현 자체로 해결할 수 있는 내용이 확정되면 `KO-*` 근거로 한국어를 다듬는다. 보존할 것은 확인한 제품 의미이며 사실과 다른 기존 주장을 유지하라는 뜻이 아니다. 없던 번역투나 어법 오류를 만들어내거나 버튼 어형을 다루는 KO-05를 링크의 근거로 자동 확대하지 않는다.

출처 하나가 UX와 한국어를 함께 다뤄도 적용한 주장과 책임을 구분한다. 자연스러운 어순을 근거로 필수 안내를 삭제하거나, 필요한 안내를 근거로 특정 높임말을 강제하지 않는다.

목적지 화면을 읽지 못했어도 신뢰할 사양에 이동 목적이 명시돼 있다면 그 사실만으로 판단 가능한 레이블을 부분 수정할 수 있다. 목적지 상태·결과·복구까지 확인한 것으로 취급하지 않으며 해당 경로는 보류한다. 확인하지 못한 사실에 의존하는 변경은 적용하지 않는다.

## 수정과 보존

문자열 전체 검색·일괄 치환을 피한다. 같은 글자라도 퍼널의 역할이 다르면 각자 판단한다. 공용 키가 다른 맥락을 겸해 한 문구로 해결할 수 없으면 사용처별 분리가 필요한 이유를 보고한다. 이미 허용된 범위의 문구 리소스 분리는 모든 호출부와 테스트를 함께 갱신하고 행동은 유지한다.

흐름 구현 허용을 기존 외국어 문구의 번역 허용으로 해석하지 않는다. 흐름 구현이 허용되어 원래 없던 문구를 추가한다면 `additions`에 별도로 기록한다. 기존 문구의 원문·진단·결정은 그대로 보존하고, 새 문구에는 허용 범위·추가 이유·연결된 흐름 문제·사용처별 검토를 남긴다. 새 화면과 문구는 `recheck`에서 확인한다. 자세한 형식은 [감사 기록 형식](audit-format.md)을 따른다.

번역 키·API 식별자·분석 이벤트·오류 코드를 문장으로 오인해 바꾸지 않는다. 명령형 대화상자, 화면 텍스트, 접근성 이름이 같은 행동을 가리키는지 함께 확인한다. 원문 해시나 현재 텍스트를 다시 대조한 뒤 패치해 다른 변경을 덮어쓰지 않는다.

동적 문장은 실제 렌더링 결과로 확인한다. 변수 이름·개수·타입, ICU 선택 분기, 복수형, 숫자·날짜 형식, 태그 구조를 보존한다. 자동 검사가 다루지 못하는 문법과 의미는 수동 검토 항목에 남긴다.

좋은 문구는 `keep`, 근거나 맥락이 부족한 문구는 `blocked`로 남긴다. 각 결정에는 사용처별 UX 이유와 한국어 이유를 따로 남긴다. 같은 일반 사유를 복사해 유지 결정을 채우지 않는다.

문서화된 말투·용어는 제약으로 확인하며 기존 문구 자체를 좋은 한국어의 증거로 삼지 않는다. 특정 영어의 고정 대체어, 임의 금칙어·점수, 해요체·능동형·긍정형의 일괄 강제는 사용하지 않는다. 조건·부정·예외·책임 주체·확정성·금액·기간·단위·변수·접근성 연결을 보존한다.

허용된 재배치는 기존 발생 위치와 `final_location`을 연결한다. 새 안내는 `additions`로 구분하며 없던 원문·진단을 만들지 않는다. 제안만 한 흐름 변경을 적용·해결한 것으로 기록하지 않는다.

실제 diff와 원문·결정을 대조한 뒤 [4. 재검증](verification.md)을 읽는다. 윤문을 끝냈다는 이유로 흐름 문제를 닫지 않는다.
