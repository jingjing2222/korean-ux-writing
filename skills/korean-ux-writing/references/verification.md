# 4. 재검증

1단계의 과업·예상과 3단계의 결정·diff를 바탕으로 같은 과업을 다시 따라간다. 수정 전 기록을 덮어쓰지 않고 결과를 `recheck`에 남긴다. 기존 경로를 재검토한 기록에는 `original_path_id`로 원래 `paths`의 ID를 연결한다. 새 경로에는 없는 원래 ID를 만들지 않는다. 원문·진단·행동 전 기록의 보존과 경로 ID별 재검토 누락은 마지막에 도구로 검사한다.

## 해결했다고 한 차이를 다시 확인한다

- 모든 사용처와 분기를 다시 읽고 앞 단계의 약속, 현재 선택, 뒤 단계 결과가 맞는지 확인한다. 원문이 유지·이동·삭제된 곳도 확인한다.
- 고친 문구만으로 독자가 필요한 대상·행동·조건·결과를 알 수 있는지 설명한다. 내부 용어를 하나 지우거나 문장을 짧게 한 사실만으로 해결했다고 하지 않는다.
- 문서는 [약속과 실행 조건](reader-language.md#문서의-약속과-실행-조건-점검)을 다시 대조한다. 이후 작업의 제약이 처음 필요한 선택 시점에서 제공되는지, 예시와 필수 조건이 구별되는지, 보호 경계와 결과가 식별되는지 확인한다. 명령 앞의 경고만으로 더 앞선 선택의 문제를 닫지 않는다.
- 다른 언어·로케일·혼합 문장의 보존 대상과 코드·명령을 원문 및 diff로 대조한다. 토큰 검사만으로 선언하지 않은 변경이나 뜻의 보존을 보증하지 않는다. 범위를 벗어난 자신의 변경만 되돌리고 사용자의 기존 변경은 보존한다.
- 가능한 환경에서 화면·줄바꿈·접근성·동적 값과 실제 결과를 확인한다. 소스 확인은 실행 관찰과 구분한다.

새 문제를 발견하면 관련 맥락 또는 진단 단계로 돌아가 갱신하고, 그 판단에 의존하는 수정만 다시 확인한다. 이전에 적합한 문구를 새 근거 없이 다시 고치지 않는다.

## 완료 판단

검증 도구는 저장된 진단과 원문·사용처·이전 예상의 일치, 기존 발견의 보존, 필수 기록과 참조를 검사한다. 완료 보고에서는 원래 경로마다 `original_path_id`가 연결된 재검토도 요구한다. 연결만 맞춰도 실제 같은 과업을 검토했다는 증거는 아니므로, 에이전트는 정보·행동·결과의 의미를 확인한다.

완료를 보고하려면 선언한 한국어 윤문 범위의 모든 문구와 사용처에 판정이 있고, 전체 퍼널과 분기가 읽혔으며, 사용자 관점 기록과 코드·내용·화면 검증을 실제로 확인해야 한다. 실행 환경이 없어 화면 확인을 못 했거나 경로를 재현하지 못했다면 `unresolved`에 남기고 부분 결과로 보고한다. 남은 흐름 문제도 같은 목록에 연결하며 윤문을 마쳤다는 이유로 전체 UX가 개선되었다고 하지 않는다.

## 감사와 결과 보고

```sh
<skill-directory>/scripts/kuw audit .reports/korean-ux-writing/revision-1/audit.json --require-checkpoint --require-complete
```

[감사 형식](audit-format.md)에 따라 결정을 완성한다. 해결하지 못한 `ux_findings`와 실행하지 못한 검증은 `unresolved`에도 남긴다. 부분 검토는 `complete: false`로 두고 위 명령에서 `--require-complete`만 뺀다. `--require-checkpoint`는 유지한다. 완료 검사를 통과시키려고 미확인 범위를 없애지 않는다.

검토 범위, 사용자에게 전달되지 않았던 정보와 표현의 차이, 수정·유지·보류 수, 남은 흐름 문제와 검증 결과를 짧게 알린다. 에이전트 사전 점검인지 실제 참여자 관찰인지, 정적 확인인지 실행 확인인지 밝힌다. 자연스러움·사용자 이해·검토 순서는 구조 검사로 증명되지 않는다.
