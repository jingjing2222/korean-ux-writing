# 직역체를 윤문 전에 진단하는 근거

진단의 중심은 **현재 한국어가 전체 사용 흐름에서 필요한 뜻과 행동을 정확하게 전달하는가**이다. 처음부터 한국어로 만든 제품을 기본 대상으로 삼고, 직접 쓴 한국어에서도 번역한 듯 느껴지는 어휘·결합을 살핀다. 이때 번역 여부나 출처를 추정하지 않는다. [의도·맥락 우선 진단 근거](intent-first.md)에 Microsoft의 세부 패시지와 한국어 제품 사례, 퍼널 추적에 적용한 해석을 정리했다. 문법 검사에만 맡기지 않는다.

아래 번역·현지화 자료의 원래 대상은 번역 작업이다. 이 레포는 그중 의미·문맥·사용 관습에 관한 원칙을 한국어 원문에 적용한다. 영어 원문을 찾거나 가상으로 만들지 않으며, 실제 영문 자료가 있을 때만 보조 맥락으로 참조한다.

## 의도와 한국어 사용 관습

|---|---|---|
| 현재 표현이 사용자가 수행할 과업을 제대로 가리키는가 | [Microsoft 한국어 가이드](https://aka.ms/korean-styleguide), 5쪽 §2.1·2.1.1, 9~10쪽 §2.1.4. 번역할 때 전체 의도를 이해하고 페이지 맥락에서 한국어로 재구성하도록 한다. [SRC-059](sources.md#src-059) | 한국어 원문에 적용하는 것은 운영상 해석이다. Microsoft 말투·용어를 보편 규범으로 삼지 않는다. |

위 자료를 실행 절차로 연결한 해석은 다음과 같다. 모든 문구에서 코드·사양으로 확인한 **안내 의도와 행동**을 적고, 현재 한국어의 **어휘·결합이 그 역할에 맞는 이유**를 따로 적는다. 두 항목이 연결되지 않으면 문법이 맞더라도 수정 후보가 된다. 이 절차가 외부 문서에 그대로 적힌 자동 판별 알고리즘이라는 뜻은 아니다.

사용자의 `Keep editing → 계속 수정` 예시는 번역한 듯 느껴지는 문제를 설명하며, 대상 제품에 영어 원문이 있다는 전제가 아니다. 검토 대상은 현재 한국어다. 대상이 게시글인지 이미지인지, 버튼이 이탈 취소인지 작업 재개인지 등을 읽고 판단한다. 문서들이 이 표현을 직접 판정한 것은 아니므로 특정 대안으로 일괄 치환하지 않는다.

이 근거들은 표현을 살펴볼 출발점이다. 특정 형태가 있으면 오류, 없으면 자연스러운 한국어라는 결론을 내리지 않는다. 새로운 문제 유형은 확인한 출처와 적용 범위를 보강한 뒤 등록한다.

## 기록과 수정의 관계

진단은 수정·유지 결정 전에 수행한다. 과업의 사실과 필요한 안내 의도를 먼저 확인하고, 현재 한국어가 그 뜻을 전달하는지 진단해 수정 전 한국어 대장과 함께 저장한다. 그 뒤 의미를 바로잡는 재작성과 문체·표기 수정을 진행한다. 판정의 책임은 다음과 같이 나눈다.

- 제품 자료: 실제로 무엇이 일어나는가.
- UX 근거: 사용자가 무엇을 알아야 하는가.
- 한국어·지역화 근거: 그 뜻을 이 상황의 한국어로 어떻게 전달할 것인가.

개선문 전체가 원문 자료에 실려 있어야 한다는 뜻은 아니다. **수정 기준과 적용 이유**가 출처에 근거해야 한다. 에이전트가 만든 점수·금칙어·취향을 새로운 기준으로 쓰지 않는다. 일반적인 과장, 군더더기, 맞춤법 오류도 고칠 수 있지만 모두 번역투라고 묶지는 않는다.
