# 직역체를 윤문 전에 진단하는 근거

진단의 중심은 **영어 표현을 따라 만든 단어·결합이 한국어 UI의 사용 상황에 맞는가**이다. 문법 검사에만 맡기지 않는다. 뜻은 짐작할 수 있어도 한국어에서 그 행동을 부르는 방식과 다르면 검토할 대상이다.

## 의도와 한국어 사용 관습

| 확인할 문제 | 실제 근거와 확인 위치 | 적용 한계 |
|---|---|---|
| 원문 낱말을 옮기느라 사용자가 수행할 과업을 놓쳤는가 | [Microsoft 한국어 가이드](https://aka.ms/korean-styleguide), 5쪽 §2.1·2.1.1, 9~10쪽 §2.1.4. 전체 의도를 이해하고 페이지 맥락에서 한국어로 재구성하도록 한다. [SRC-059](sources.md#src-059) | Microsoft 말투·용어를 보편 규범으로 삼지 않는다. |
| 한국에서 잘 쓰지 않는 표현이나 의도와 다른 용어인가 | [pxd의 사용성 관찰](https://story.pxd.co.kr/1383), 테스트 결과와 용어 친숙도 사례. [SRC-010](sources.md#src-010) | 대상 사용자의 경험에 따라 다르며 외래어 일괄 금지가 아니다. |
| 영어로 부른 이름보다 사용 목적을 드러내는 이름이 필요한가 | [현대차 UX팀 인터뷰](https://www.hyundaimotorgroup.com/ko/story/CONT0000000000176495), 고객 언어 협의체와 타깃별 예외. [SRC-062](sources.md#src-062) | 전문 사용자는 익숙한 기술 용어가 더 적절할 수 있다. |
| 뜻과 메시지를 이해한 뒤 한국어로 표현했는가 | [Mozilla 한국어 가이드](https://mozilla-l10n.github.io/styleguides/ko/)와 연결된 [Meaning-based translation](https://mozilla-l10n.github.io/styleguides/mozilla_general/). [SRC-060](sources.md#src-060)·[061](sources.md#src-061) | 의미를 추가·삭제하거나 새로운 기능을 안내할 허가는 아니다. |
| 같은 영어라도 역할·앞뒤 맥락이 다른가 | [Apple 번역 맥락 설명](https://developer.apple.com/kr/videos/play/wwdc2025/225/), 5:33~9:33. [Chromium 메시지 의미 구분](https://www.chromium.org/developers/design-documents/ui-localization/). [SRC-063](sources.md#src-063)·[064](sources.md#src-064) | 맥락 확인의 근거이며 개별 한국어 대체어의 정답은 아니다. |

위 자료를 실행 절차로 연결한 해석은 다음과 같다. 모든 문구에서 코드·사양으로 확인한 **안내 의도와 행동**을 적고, 현재 한국어의 **어휘·결합이 그 역할에 맞는 이유**를 따로 적는다. 두 항목이 연결되지 않으면 문법이 맞더라도 수정 후보가 된다. 이 절차가 외부 문서에 그대로 적힌 자동 판별 알고리즘이라는 뜻은 아니다.

사용자의 `Keep editing → 계속 수정` 예시는 이 문제를 설명한다. 문서들이 이 표현을 직접 판정한 것은 아니다. 따라서 특정 대안으로 일괄 치환하는 규칙으로 만들지 않는다. 대상이 게시글인지 이미지인지, 버튼이 이탈 취소인지 작업 재개인지 등을 읽고 해당 의미에 맞는 한국어를 검토한다. 영문 원문이 없는 경우 영어에서 번역됐다고 단정하지 않는다.

## 보조적으로 확인할 문장 구조

| 유형 | 근거 | 반드시 함께 볼 예외 |
|---|---|---|
| 구문·서술어의 기계적 대응 | [김순영, 영한 번역투](sources.md#src-053), 인쇄 72~75쪽 | 피동·가지다 자체는 오류가 아니다. [국립국어원 피동 답변](sources.md#src-057)과 함께 본다. |
| 복수 표시 | 같은 글, 76쪽 | 복수의 뜻과 강조를 보존한다. 시제까지 확장하지 않는다. |
| 전치사구의 의미관계 | 같은 글, 76~77쪽; [최희경의 코퍼스 연구](sources.md#src-055), 155~164쪽 | 통하다·로부터만으로 번역 기원이나 낮은 품질을 판정하지 않는다. |
| 일한 어휘·쉼표 | [김한식, 일한 번역투](sources.md#src-054), 89~95쪽 | 정착한 용법과 동형 한자어의 의미 차이를 살핀다. |
| 에 있어서 | [국립국어원 답변](sources.md#src-058), 2026-05-21 | 번역투로 알려졌다는 사실과 문법 오류 여부는 다르다. |

이 근거들은 표현을 살펴볼 출발점이다. 특정 형태가 있으면 오류, 없으면 자연스러운 한국어라는 결론을 내리지 않는다. 새로운 문제 유형은 확인한 출처와 적용 범위를 보강한 뒤 등록한다.

## 기록과 수정의 관계

진단은 수정·유지 결정 전에 수행한다. 먼저 원문 대장과 진단을 저장하고, 그 뒤 UX 기준으로 필요한 안내를 확정한 다음 한국어 기준으로 표현을 다듬는다. 판정의 책임은 다음과 같이 나눈다.

- 제품 자료: 실제로 무엇이 일어나는가.
- UX 근거: 사용자가 무엇을 알아야 하는가.
- 한국어·지역화 근거: 그 뜻을 이 상황의 한국어로 어떻게 전달할 것인가.

개선문 전체가 원문 자료에 실려 있어야 한다는 뜻은 아니다. **수정 기준과 적용 이유**가 출처에 근거해야 한다. 에이전트가 만든 점수·금칙어·취향을 새로운 기준으로 쓰지 않는다. 일반적인 과장, 군더더기, 맞춤법 오류도 고칠 수 있지만 모두 번역투라고 묶지는 않는다.
