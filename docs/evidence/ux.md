# UX 역할의 근거

이 축은 프론트엔드 코드가 수행하는 역할과 사용자 흐름에 맞춰 **무엇을 안내할지** 판단하는 데 사용한다. 컴포넌트 이름만으로 의미가 확정되지는 않는다. 실제 이벤트, 조건 분기, 앞서 한 안내, 실행 뒤 결과는 제품에서 확인한다.

제품의 전체 맥락이 사용자의 이용 맥락을 대신하지 않는다. [사용자 관점과 안내 시점](user-perspective.md)의 근거로 실제 과업과 전달된 정보를 먼저 확인한다. 이해에 필요한 선행 맥락이 없으면 현재 레이블을 늘리는 대신 흐름의 어디에서 그 맥락을 제공해야 하는지 검토한다.

[의도·맥락 우선 진단 근거](intent-first.md)는 전체 과업을 읽고 현재 한국어의 의미를 대조하는 선행 검토를 설명한다. 문법과 말투가 자연스럽더라도 과업에 필요한 정보나 행동을 잘못 가리키면 먼저 그 문제를 다룬다.

아래 연결은 이 프로젝트의 운영상 분류다. 원문이 모든 프레임워크의 코드 역할을 정의했다는 뜻은 아니다. 원문 주장·적용 조건·예외는 각 출처 카드에 기록했다.

## 역할별 연결

| 화면·동작의 역할 | 원문에서 확인할 안내 내용 | 증적 |
|---|---|---|
| 실행 버튼 | 실행될 기능을 예측하는 레이블, 일반 작업과 길이·해석의 예외 | [SRC-019](sources.md#src-019) |
| 이동 링크 | 목적지 예측, 주변 맥락, 같은 목적지의 명칭 | [SRC-020](sources.md#src-020) |
| 선택 목록 | 무엇을 선택하는지, 레이블 생략 조건, 잘린 옵션 확인 | [SRC-021](sources.md#src-021) |
| 태그 추가·삭제 | 분류 대상과 동작, 접근 가능한 이름 | [SRC-022](sources.md#src-022) |
| 여러 단계의 진행 | 단계별 작업과 실제 건너뛰기 동작 | [SRC-023](sources.md#src-023) |
| 도움 패널 | 본문과 도움말의 제목·레이블 대응 | [SRC-024](sources.md#src-024) |
| 기능 안내·코치마크 | 간결한 지시, 현재·마지막 단계에 맞는 액션 | [SRC-025](sources.md#src-025) |
| 날짜 입력 | 날짜의 의미, 실제 입력 형식·자릿수·예시 | [SRC-026](sources.md#src-026) |
| 긴 텍스트 입력 | 입력 목적과 실제 글자 수 제한 | [SRC-027](sources.md#src-027) |

| 파일 업로드 | 제출 용도와 실제 파일 유형·크기·개수·오류 | [SRC-029](sources.md#src-029) |
| 개인 식별 정보 입력 | 요청 목적, 입력 대상, 실제 형식 제약 | [SRC-030](sources.md#src-030) |
| 도움말 | 사용자 관점의 설명, 명칭 일관성, 필수 정보의 위치 | [SRC-031](sources.md#src-031) |
| 동의 | 필수·선택 항목 구분과 항목·옵션의 연결 | [SRC-032](sources.md#src-032) |
| 상세 정보 | 제목과 앞부분에서 드러나는 핵심 내용 | [SRC-033](sources.md#src-033) |
| 오류 | 오류 종류·위치와 확인된 수정 방법 | [SRC-034](sources.md#src-034), [SRC-002](sources.md#src-002) |
| 입력폼 전체 | 실제 단위·필수 여부·오류 항목의 일치 | [SRC-035](sources.md#src-035) |

KRDS 자료는 정부서비스를 위한 지침이다. 역할 설명은 참고할 수 있으나 태그의 단어 수처럼 구체적인 제약을 모든 제품 문구에 확대하지 않는다. 오류 원인, 동의의 필수성, 파일 제한, 검색 범위는 KRDS가 대상 제품에 대신 정해 주는 사실이 아니다.

## 흐름과 사용 맥락을 보완하는 자료

| 확인할 문제 | 확인한 외부 내용 | 증적 |
|---|---|---|
| 행동을 예고하는 문구와 실제 결과가 다른가 | 다음 행동을 예측하는 표현, 충전 후 안내·입력 용도 개선 사례 | [SRC-001](sources.md#src-001), [SRC-009](sources.md#src-009), [SRC-011](sources.md#src-011) |
| 오류 설명이 실제 발생·복구 조건과 연결되는가 | 오류 상황·이유·해결책과 보안 예외, 개발자와의 발생·해결 조건 확인 사례 | [SRC-002](sources.md#src-002), [SRC-003](sources.md#src-003) |
| 제품의 말투·명칭·공용 문구가 서로 맞는가 | 실제 제품 사례에서 규칙을 만드는 운영, 컴포넌트별 관리 | [SRC-004](sources.md#src-004), [SRC-005](sources.md#src-005) |
| 대상 사용자가 질문·용어를 다른 뜻으로 읽는가 | 시니어의 질문형 문구 오인지, 탐색 명칭 사용성 관찰 | [SRC-006](sources.md#src-006), [SRC-010](sources.md#src-010) |
| 누가 어느 상황에서 읽는가 | POS·계산대의 독자와 상황에 맞춘 안내 | [SRC-007](sources.md#src-007) |
| 문구가 제약을 흐리거나 정보량이 과업에 맞지 않는가 | 불리한 상황도 정확하게 전달, 과업에 따른 정보량, 주요 메시지와 상세 정보 구성 | [SRC-008](sources.md#src-008), [SRC-015](sources.md#src-015), [SRC-016](sources.md#src-016), [SRC-017](sources.md#src-017) |
| 짧게 줄이면서 실제 행동·불가 조건이 바뀌는가 | 버튼 목적별 표현 차이, 포괄적 오류의 문제, 상황에 따른 긍정·부정문 | [SRC-012](sources.md#src-012), [SRC-013](sources.md#src-013), [SRC-014](sources.md#src-014), [SRC-018](sources.md#src-018) |

제품 사례와 전문가 원저술은 해당 사례의 해석과 제안이다. 별도의 사용자 검증 없이 보편적인 효과나 금칙어 규칙으로 승격하지 않는다.

## 한국어 근거와 겹치는 자료

키오스크 언어 실태 조사 [SRC-041](sources.md#src-041)는 실제 UI 언어의 오류·접근성 문제를 다룬다. 쉬운 언어 사용 모형 [SRC-042](sources.md#src-042)는 고령층의 이해도·수용도 확인을 다룬다. 두 자료는 UX 역할과 한국어 표현 양쪽에 걸치지만, SRC-042의 세부 개선안·효과 수치는 아직 검증하지 않았다.

정확성과 소통성을 구분하는 연구 [SRC-046](sources.md#src-046)는 평가 축을 구분하는 보조 근거다. 해당 연구의 문서별 점수·가중치를 UI의 합격 점수로 복제하지 않는다.
