# 윤문보다 먼저, 사용자 의도에 맞는 한국어인지 확인하기

문법적으로 맞는 한국어라도 사용자가 하려는 일과 다른 뜻으로 읽힐 수 있다. 이 검토의 출발점은 어미를 부드럽게 바꾸는 일이 아니라, **사용 흐름에서 전달해야 할 뜻을 확인하고 현재 표현이 그 뜻을 전달하는지 판단하는 일**이다.

기본 대상은 **처음부터 한국어로 만든 제품의 프런트엔드 문구**다. 영어 원문을 찾거나 가상의 영문으로 역번역해 비교하지 않는다. 제품의 흐름과 현재 한국어를 직접 검토하며, 실제 영문 자료가 있을 때만 보조 맥락으로 참조한다. 번역 기원을 알아내는 작업이 아니다.

아래는 확인한 외부 자료와 이 레포의 적용 방식을 구분한 기록이다. 같은 자료의 여러 절을 별개 출처로 세지 않는다. 개별 자료의 성격·한계·확인 상태는 [출처 카드](sources.md)에 둔다.

이 글에서 제품을 이해한다는 것은 실제 동작을 확인한다는 뜻이다. 사용자 과업과 이해 가능성은 [사용자에게 전달된 맥락과 안내 시점](user-perspective.md)의 근거로 따로 판단한다. 선행 맥락이 빠진 문제는 현재 표현을 늘리는 대신 흐름 개선 사항으로 다룬다.

## Microsoft 한국어 가이드에서 직접 확인한 내용

[SRC-059](sources.md#src-059)의 [한국어 현지화 가이드](https://aka.ms/korean-styleguide)는 55쪽 PDF다. 다음 위치는 PDF에 표시된 쪽 번호이며, 표의 올바른 번역·잘못된 번역 열을 직접 확인했다.

이 가이드의 직접 대상은 번역·현지화 작업이다. 이 레포는 그중 전체 의도·사용 맥락·어휘 적합성을 살피는 원칙을 한국어로 작성된 문구의 검토에 적용한다. 이는 레포의 운영상 해석이며, 가이드가 한국어 원문 윤문을 직접 지시했다고 주장하지 않는다.

| 확인 위치 | 원문에서 확인한 주장 | 적용할 때 지킬 범위 |
|---|---|---|
| §2.1, p5 | 독자와 과업에 필요한 정보를 기준으로 의도를 전달하며, 통상적인 번역 대응어와 다른 말도 선택할 수 있다. | 기술 독자와 일반 소비자에게 적절한 어휘는 다를 수 있다. |
| §2.1.1, p5 | 문장·단락·페이지의 전체 의도를 이해한 뒤 한국어 작성자처럼 다시 구성한다. | 불필요한 내용의 생략을 사실·조건 삭제로 확대하지 않는다. |
| §2.1.3, pp8–9 | 익숙한 일상 표현과 승인된 용어를 함께 고려한다. | 기술 용어·제품명을 일괄 순화하지 않는다. |
| §2.1.4, pp9–10 | 실제 페이지에서 맥락을 확인하고 단어별 대응을 피한다. | 맥락 없는 문자열 목록만으로 판단하지 않는다. |
| §4.1.6, p26 | 관용 표현의 표면형보다 의도를 보존하며 한국어로 재구성한다. | 한국어 관용구로 기계적으로 바꿔도 무례해질 수 있다. |
| §5, pp32–33 | 처음부터 한국어로 작성한 제품 같은 표현과 용어 일관성을 함께 요구한다. | 자연스러움을 이유로 같은 개념의 이름을 흔들지 않는다. |
| §5.4.2, pp38–39 | 오류 안내도 영문 형태를 그대로 따르지 않으며 표준 번역을 문맥에 맞게 조정할 수 있다. | Microsoft의 종결형 정책은 다른 제품의 의무가 아니다. |

p10의 `Stay in touch with Windows` 사례는 Windows와 연락한다는 표면 대응보다 관련 소식을 전한다는 의미로 옮기도록 한다. 문제는 맞춤법이 아니라 **이 상황에서 무엇을 말하려는지**다. 이 사례를 모든 연락·연결 표현에 적용하는 치환 규칙으로 쓰지 않는다.

## 외부 원칙을 실행 절차로 연결한 해석

다음 절차는 이 레포의 운영 설계다. 외부 문서가 동일한 필드·순서의 자동 판별 알고리즘을 제공했다고 주장하지 않는다.

1. **사용자에게 필요한 맥락부터 확인한다.** 과업의 근거 또는 가설, 해당 경로에서 제공된 정보, 행동 전 예상과 실제 결과를 구분한다. 코드·사양으로는 동작 사실을 대조한다. 필요한 선행 맥락이 없으면 안내를 처음 제공해야 하는 단계를 찾으며, 존재하지 않는 영어 문장으로 의도를 정하지 않는다.
2. **현재 한국어를 의도와 대조한다.** 단어의 뜻, 함께 쓰인 말, 가리키는 대상과 행동, 주변 선택지와의 구별을 본다. 문법 오류가 없어도 이 관계가 어긋날 수 있다.
3. **판단 근거와 예외를 적는다.** 어떤 외부 기준이 적용되고, 이 발생 위치에서 무엇이 어긋나는지 설명한다. 전문 용어·제품명·독자 관습·공용 사용처 때문에 유지해야 하는 경우도 확인한다.
4. **진단이 끝난 뒤 고친다.** 확인한 뜻을 한국어로 다시 구성한 다음 길이·어미·중복·맞춤법을 다듬는다. 표현만 매끄럽게 만들어 잘못된 의미를 남기지 않는다.
5. **같은 흐름에서 다시 읽는다.** 이전 안내, 선택지, 실행 결과, 후속 화면의 뜻이 이어지는지 검토한다. 화면이나 경로를 확인하지 못한 부분은 미확인으로 남긴다.

UX 근거는 사용자가 알아야 할 것을 판단하고, 한국어·지역화 근거는 그 뜻을 이 상황에서 전달하는 방식을 판단한다. 두 책임을 합쳐 하나의 취향 점수로 만들지 않는다.

## 진단할 문제와 과잉 교정의 경계

| 검토할 문제 | 진단에서 설명할 내용 | 근거와 경계 |
|---|---|---|
| 상황과 맞지 않는 어휘 | 실제 대상·행동과 현재 한국어가 가리키는 뜻의 차이 | SRC-059·075의 원칙을 한국어 원문 검토에 적용한다. 번역 기원은 판정하지 않는다. |
| 어휘 결합·관용 표현의 표면 대응 | 낱말별 뜻은 맞아도 이 사용 상황의 전달 의도가 빗나가는 이유 | SRC-059·061. 막연히 어색하다는 인상만으로 오류라고 하지 않는다. |
| 흐름에서 역할을 알 수 없는 범용 동사 | 무엇을 계속·완료·취소하는지, 사용자 선택 뒤 무엇이 달라지는지 | SRC-066·067·069. 범용 동사 자체를 금칙어로 만들지 않는다. |
| 다른 선택지를 구분하지 못하는 표현 | 선택지별 동작·결과의 실제 차이 | SRC-066·069. 표현을 달리하기 위해 기능 차이를 만들어내지 않는다. |
| 공유 문자열의 의미 충돌 | 각 사용처에서 요구하는 뜻이 같은지 다른지 | SRC-067. 같은 맥락에서의 재사용까지 금지하지 않는다. |

일반 원칙이 있다고 해서 개별 단어가 한국어에서 드물거나 부적절하다는 사실까지 입증되는 것은 아니다. 그런 판단에는 해당 맥락의 의미 대조와 확인한 사용례·언어 자료·사용자 연구가 필요하다. 근거가 부족하면 불확실성을 남기고, 대안이 더 우수하다고 단정하지 않는다.

사용자가 제시한 `Keep editing → 계속 수정`은 표현이 번역한 듯 느껴지는 문제를 설명하는 예시다. 검토하는 제품에 영어 원문이 존재한다는 뜻은 아니다. 실제 대상은 `계속 수정`이라는 한국어이며, 새 글 작성 중의 이탈 취소인지, 기존 정보 수정의 재개인지, 이미지 편집인지에 따라 판단한다. 외부 자료가 이 표현 자체의 정오나 특정 대안을 판정한 것은 아니므로 고정 치환하지 않는다.

형태 중심의 보조 점검은 [직역체 진단 근거](translationese.md)를 따른다. 피동·복수·전치사 대응을 고쳤다는 이유만으로 위의 의미·맥락 진단을 마친 것으로 보지 않는다.
