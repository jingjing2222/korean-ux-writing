# Korean UX Writing

한국어 · [English](README.en.md)

프론트엔드의 한국어 문구를 사용자의 관점에서 검토하고 다듬는 스킬입니다. 사용자가 실제로 받은 안내만으로 다음 행동과 결과를 이해할 수 있는지 살핍니다. 영어 원문은 필요하지 않습니다.

공개된 UX 지침과 한국어 자료를 근거로 검토합니다. 앞 단계의 안내가 빠져 이해하기 어렵다면 흐름의 문제부터 짚고, 표현을 다듬는 일은 그다음에 합니다.

## 설치

Codex나 Claude Code에 플러그인으로 설치합니다.

### Codex

터미널에서 다음 명령을 차례대로 실행하세요.

```sh
codex plugin marketplace add jingjing2222/korean-ux-writing
codex plugin add korean-ux-writing@korean-ux-writing
```

### Claude Code

Claude Code 대화창에서 명령을 한 줄씩 실행하세요. 두 번째 명령으로 열린 화면에서 설치할 범위를 선택하세요.

```text
/plugin marketplace add jingjing2222/korean-ux-writing
/plugin install korean-ux-writing@korean-ux-writing
```

설치를 마치면 새 대화에서 요청하세요. 이 저장소의 마켓플레이스로 배포하며, 두 제품의 공식 플러그인 목록에는 등록되어 있지 않습니다.

## 이렇게 요청하세요

전체 프론트엔드를 검토하려면:

```text
korean-ux-writing 스킬로 프론트엔드의 한국어 문구를 빠짐없이 검토해 줘.
문구마다 원문과 검토 후 문구, 판단 이유와 근거를 정리하고 코드에 반영해 줘.
```

특정 흐름부터 시작하려면:

```text
korean-ux-writing 스킬로 회원가입 흐름의 문구를 다듬어 줘.
첫 화면부터 오류가 났을 때의 대응, 가입 완료까지 함께 확인해 줘.
```

## 어떻게 진행되나요?

1. **사용자의 과업을 따라갑니다.** 시작부터 선택, 취소·오류 대응, 완료까지 살핍니다. 각 단계에서 사용자가 받은 안내와 예상할 수 있는 결과를 확인합니다.
2. **문구가 쓰이는 곳을 확인합니다.** 버튼, 입력 안내, 오류, 빈 화면, 알림, 접근성 문구 등을 모으고 언제 어디에 나타나는지 기록합니다.
3. **문구 문제와 흐름 문제를 구분합니다.** 필요한 맥락을 앞서 전달하지 않았다면 어느 단계에서 안내해야 하는지 제안합니다. 개발자가 아는 내용을 사용자도 안다고 가정하거나, 현재 문구에 설명을 덧붙여 해결 처리하지 않습니다.
4. **표현이 사용자의 과업에 맞는지 확인한 뒤 다듬습니다.** 문법이 맞아도 상황에 맞지 않는 단어나 모호한 표현을 찾습니다. 같은 문구도 쓰이는 곳에 따라 따로 판단하고, 뜻을 바로잡은 뒤 문장을 다듬습니다.
5. **수정 전후를 비교하고 다시 확인합니다.** 문구마다 원문과 검토 후 문구, 판단 이유와 근거를 남깁니다. 가능한 환경에서는 실제 화면도 확인합니다.

모든 문구는 **수정·유지·보류**로 구분합니다. 실제 기능과 변수, 금액·기간·조건 등 중요한 정보는 유지합니다. 안내가 실제 동작과 다르면 확인한 사실에 맞게 고치고, 정보가 부족하면 보류한 이유와 더 확인할 내용을 남깁니다.

## 어떤 근거를 사용하나요?

[근거 자료](docs/evidence/README.md)에 참고한 원문의 링크와 적용 범위, 예외를 정리했습니다. 이 자료는 스킬과 별도로 관리합니다.

- **UX 자료**는 해당 상황에서 무엇을 안내해야 하는지 판단하는 데 씁니다.
- **한국어 자료**는 현재 표현이 문맥에 맞는지 판단하고 문장을 다듬는 데 씁니다.
- **제품 코드**는 실제 동작과 조건을 확인하는 데 씁니다.

공식 지침, 사용성 조사, 전문가의 제안은 구분해 참고합니다. 해요체나 특정 브랜드의 말투를 모든 제품에 똑같이 적용하지 않습니다.

## 사용 범위

이미 있는 한국어 UI 문구를 검토하고 다듬는 스킬입니다. 한국어가 없는 제품을 처음부터 번역하거나 새 콘텐츠를 쓰는 작업은 따로 요청해야 합니다.

접근하지 못한 화면과 해결하지 못한 흐름 문제도 결과에 남깁니다. 에이전트의 사전 점검은 실제 사용자를 관찰하는 사용성 테스트와 구분합니다.

자세한 검토 절차와 완료 기준은 [SKILL.md](skills/korean-ux-writing/SKILL.md)에서 확인할 수 있습니다.
